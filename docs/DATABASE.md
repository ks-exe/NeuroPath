# Database

PostgreSQL is the target database (local: `postgres:16-alpine` in Compose). Access goes through SQLAlchemy 2.x; schema changes go through Alembic.

## Migration strategy

- **Alembic only.** Every schema change is an Alembic revision in `apps/api/alembic/versions/`. No `create_all()`, no manual DDL.
- **Phase scope.** A phase's migrations create only the tables Appendix B.3 lists for that phase (R6.3).
- **Reversible.** Every revision has a working `downgrade()`.
- **Round-trip check.** The phase gate (`--phase 0` and `--phase 1`) runs this check on a fresh SQLite database unless `--database-url` is given. `scripts/check_migrations.py` runs on an empty database: it records the reflected schema, runs `upgrade head` then `downgrade base`, and compares the result with the starting state. Any difference fails the check (exit 1, diff printed). It refuses to touch a non-empty database. Run with `python scripts/dev.py check migrations [URL]` (see `DEVELOPMENT.md` for running without PostgreSQL).

## Naming conventions

Defined in `apps/api/models/base.py` so constraint and index names are deterministic across revisions:

| Object | Pattern |
|---|---|
| Index | `ix_%(column_0_label)s` |
| Unique | `uq_%(table_name)s_%(column_0_N_name)s` |
| Check | `ck_%(table_name)s_%(constraint_name)s` |
| Foreign key | `fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s` |
| Primary key | `pk_%(table_name)s` |

## Mixins

| Mixin | Columns |
|---|---|
| `IdMixin` | `id uuid` primary key, generated by the application (`uuid4`) |
| `TimestampMixin` | `created_at`, `updated_at`: timezone-aware, NOT NULL, server default `now()`; `updated_at` refreshes on update |
| `TenantOwned` | `organization_id uuid`, NOT NULL, indexed, FK to `organizations.id` (`ON DELETE RESTRICT`) |
| `CreatedAtMixin` | `created_at` only, for append-only tables |

`apps/api/models/__init__.py` imports every model module, so importing `models` (or any submodule) registers all tables and the `organizations` FK always resolves.

## Transactions

`core/database.py` provides `transaction(factory)`: one service call runs in one transaction, committed on success and rolled back on any error. Sessions use `autoflush=False` and `expire_on_commit=False`.

## Revisions

- `0001_baseline`: empty baseline, no tables (Appendix B.3, Phase 0).
- `0002_phase1`: the Phase 1 tables below and the internal Organization seed row. Models are in `apps/api/models/phase1.py`.
- `0003_audit_append_only`: on PostgreSQL, the function `audit_logs_reject_change()` and the `BEFORE UPDATE OR DELETE` trigger `trg_audit_logs_append_only` that raise on any change to `audit_logs` (R6.9, R30.4). No-op on SQLite.

**Audit writes.** `services/audit.py` `AuditService.record` inserts through `repositories/audit_log.py` (insert and read methods only) inside the caller's transaction, stamps the current request id, and redacts metadata (keys such as password, secret, token, authorization, cookie, api_key, card, iban become `[REDACTED]`; strings over 500 characters are truncated). A failed write raises `audit_write_failed` (HTTP 500), so the caller's transaction rolls back. `transition_audit_hook()` builds the `audit_hook` for `transition()`.

## Phase 1 tables

| Table | Owner | Phase 1 columns | Constraints and indexes |
|---|---|---|---|
| `organizations` | G | `name`, `kind` (`internal`, `client`) | CHECK on `kind`; partial unique index on `kind` where `kind = 'internal'` |
| `leads` | I (no `organization_id`) | `name`, `email`, `company`, `email_normalized_hash` | index on `email_normalized_hash`, not unique (duplicates are flagged in Phase 2, R22.5) |
| `project_inquiries` | T | `lead_id`, `submission_token`, `title`, `problem_description`, optional text fields of R14.1, `service_hint`, `entry_path` | unique `submission_token` (R14.14); CHECK on `entry_path`; `(organization_id, created_at)`; `(lead_id)` |
| `projects` | T | `project_inquiry_id`, `status` | unique `project_inquiry_id` (one Project per inquiry, R24.15); CHECK on `status` generated from the Appendix A.1 status set; no default (T01 sets Submitted); `(organization_id, status)`; `(organization_id, created_at)` |
| `consent_records` | I, nullable `organization_id` | `lead_id`, `organization_id`, `project_inquiry_id`, `consent_type` (`contact_and_processing`, `ai_processing`, `model_training`), `granted`, `wording_version`, `recorded_at` | append-only (`created_at` only); CHECK on `consent_type`; `(lead_id)`; `(organization_id, consent_type)` |
| `audit_logs` | T, nullable `organization_id` | `actor_type`, `actor_id`, `action`, `resource_type`, `resource_id`, `organization_id`, `request_id`, `metadata` (JSONB on PostgreSQL) | append-only (`created_at` only); CHECK on `actor_type`; `(organization_id, created_at)`. UPDATE/DELETE rejected by trigger (`0003_audit_append_only`); the Phase 2 search indexes come in a later revision |

All foreign keys use `ON DELETE RESTRICT`. FKs to `users` (for example `audit_logs.actor_id`, `consent_records.user_id`) are added in Phase 2 when `users` exists.

**Internal Organization.** `0002_phase1` inserts one `organizations` row with `kind = 'internal'`, name `NEUROPATH`, and the fixed id `models.INTERNAL_ORGANIZATION_ID` (`00000000-0000-4000-8000-000000000001`). Guest inquiries and their Projects are owned by it until linked to a Client Organization (Appendix B.1 item 6).
